# Cry Atlas (insecticidal 3-domain proteins of the BPPRC database)

Separate Atlas artifact built from the NODE-MSA Atlas pipeline (page copy + pack builders) for the **Cry class of bpprc-db.org**
(`https://www.bpprc-db.org/categorize_database_cry`, downloaded 2026-11-24). Nothing of the NODE-MSA Atlas (`atlas/site`, its packs, its published artifact) was edited.

## Data sources (all public)
| what | source | file |
|---|---|---|
| Cry names, old / other names, accession, year (808) | BPPRC category page `categorize_database_cry` | `data/bpprc_cry_table.tsv` |
| full-length sequences (797 records, 795 names) | BPPRC `category_download` (category = cry) | `raw/fasta/cry_full.fasta` |
| BPPRC domain sequences D1 / D2 / D3, holotype list | BPPRC `threedomain_download`, `holotype_download` | `raw/fasta/` |
| structures table (PDB ids per BPPRC name) | BPPRC `structures/` | `data/bpprc_cry_structures.tsv` |
| specificity (target order / species, active yes / no) | BPPRC `export_association` (curator column dropped) | `work/specificity.json` |
| organism, strain, plasmid, coded_by, NCBI sequence | NCBI GenPept (efetch) | `work/ncbi/genpept.json` |
| UniProt entries of identical sequences, AlphaFold DB models | UniParc (MD5) -> UniProtKB -> AlphaFold DB API; model accepted only when its sequence equals the row | `work/afdb/map.json` |
| PDB entries | RCSB (accession search + full-text candidates, entity sequences by GraphQL, local matching >= 90 %) | `work/pdb/matches.json` |
| genomic context | NCBI IPG + nuccore GenBank windows (gene +- 15 kb) | `site/data/cry/gc.json`, `work/gc_windows/` |

## Pipeline (scripts in `scripts/`, run with `py -I`; run order)
01 parse BPPRC table -> 02 FASTA + domains -> 03 clean / merge exact duplicates -> 04 GenPept -> 05 compare BPPRC vs NCBI sequences -> 06 BPPRC structures table ->
07 UniProt + AlphaFold DB map -> 08b/08c PDB candidates and entity matching -> 09 rows -> 10 / 10b sequence frame (first pass, then segment-wise MAFFT L-INS-i) -> 15 modules ->
11 specificity -> 12 download structures -> 13 RING 4.0 -> 14 assemble rows (models) -> 16b structure frame (segment-wise FoldMason) -> 17 classes -> 19 build the pack (`cry_pack.py`) ->
`verify_cry_pack.py` -> 18 / 18a / 18b genome map and synteny -> 20 trees (IQ-TREE) -> `asr/` ancestors (PAML + GRASP) -> `patch_cry_page.py` (page) -> publish.
Large raw files (AlphaFold DB, PDB, RING edge files) are in `%TEMP%\cry_raw` (re-downloadable; manifest `work/structures_manifest.tsv` with URL, size and SHA-256).

## Decisions (and why)
* **Rows** = distinct BPPRC sequences (670 from 795 names); exact duplicates are merged and all their names listed in the row. The BPPRC sequence is the entity (NCBI differences are listed in the row info).
* **Primary model** of a row = the model that places most residues of its sequence (full-length first; experimental wins a tie); the others are alternative models of the row.
* **Modules** (N-term | DI | DII | DIII | C-term, the C-terminal protoxin half) = consensus of the BPPRC domain annotation over 574 annotated rows, carried by alignment so every row gets the same boundaries.
* **NODE** of a monomeric toxin = the packages' rule applied to contacts that join two modules (domains) inside the chain: a column is strict NODE when its inter-module contacts over all models have >= 2 interaction types (one not VDW) and occur in >= 5 models.
* **Frames**: both alignments are built per module and joined (a single-pass alignment of full-length toxins stretched DI to 610 columns): structure-based = FoldMason of the AlphaFold DB models of each module (+ MAFFT --add for rows without an exact model); sequence-based = MAFFT L-INS-i of each module.

## Trees, ancestors, results of 2026-11-24 (added after the first publish)
* **Trees** (`scripts/20_trees.py`): IQ-TREE 2.3.6, fixed LG+G4, `--fast` search, SH-aLRT support (1000), seed 20261124. Full-toxin trees use the 1,402 (structure frame) / 1,261 (sequence frame) columns occupied by >= 20 % of the entries; domain trees (DI, DII, DIII) use the columns of the module and the entries with >= 100 (DI, DII) or 70 (DIII) residues of it. Eight trees in `site/data/cry/trees.json`; the tanglegram opens on the full toxin against Domain III.
* **Ancestors** (`scripts/asr/`, copy of the NODE-MSA Atlas ASR tools; PAML 4.10.10 codeml LG+G4 with the IQ-TREE branch lengths + GRASP 2.0.0): 669 internal nodes for each of the two full-toxin trees (`asr_struct_A.json`, `asr_seq_A.json`, index `asr_index.json`). Median node: mean posterior probability 0.999, PAML = GRASP at 100 % of the residues, 99.5 % identical to the nearest extant toxin; the root is uncertain (mean PP 0.60).
  GRASP's default indel method (BEP) did not finish in the 2-hour limit (killed after 2 h), PSP with all 1,402 columns ran out of Java heap at 6 GB, and PSP with CONTIGUOUS column blocks failed ("Failed to find optimal path for ancestor") because whole clades (Cry2, Cry3 ...) lack the protoxin half. The final run uses PSP with **interleaved** blocks (columns c, c + 4, c + 8 ...): `asr_parse.run_grasp` was changed accordingly. Environment: `ASR_MIN_OCC=0.2` (the occupancy of the tree columns), `ASR_GRASP_CHUNKS=4`, `ASR_GRASP_MEM=6g`, `py asr_export.py cry <key> --indel PSP`. PAML (about 3.5 h with the CPU shared) is cached in `scripts/asr/out/` (not in the repository).

## Domain-tree ancestors and species tree (2026-11-25)
* **Ancestors of the six domain trees** (DI, DII, DIII on the structure and the sequence frame; `asr_<frame>_<domain>.json`, 666-668 nodes each): `asr_lib.atlas_inputs` now cuts a domain tree out of the frame by the module code of the residues (the columns of that module, then the occupancy filter of `20_trees.py`), which reproduces the leaves and columns of every tree exactly. Same method as the full-toxin trees (PAML codeml LG+G4 + GRASP, PSP indel method; two interleaved column blocks suffice for the shorter alignments), `ASR_MIN_OCC=0.1`. `asr_export.py` merges its entry into `asr_index.json` as the file is at that moment, so several exports can run at once (six codeml jobs ran in parallel). Median node mean posterior probability 1.0; the deepest nodes are uncertain (root 0.40-0.73).
* **Species tree** (`scripts/21_species_tree.py` -> `site/data/species_tree.json`, GTDB r232 files via the environment variable `GTDB_DIR`): the organism of each row's GenPept record (first two words) matched to a GTDB species; 596 rows in 9 species (572 Bacillus thuringiensis, 10 Brevibacillus laterosporus, 4 Paenibacillus popilliae, 3 Lysinibacillus sphaericus, others 1-2), one ring per Cry class. 74 rows are not placed: no organism in the record (43), 'Unknown' (22), synthetic or genus-only names, the expression host Escherichia coli, and species GTDB does not use (Paenibacillus lentimorbus). The tree is small by nature: it shows the sources that BPPRC / NCBI name, not a genome scan.

## Activity groups, signature test, domain-tree comparison, ligand-site layer (2026-11-27)
* **Activity group** (`scripts/24_groups_and_separation.py`, applied by `27_apply_layers.py`): from the BPPRC specificity export each sequence is labelled nematode-active (19), insect-active (173), other organism only (1), tested but none active (16) or no data (461). The label is a colour-by / filter attribute ('Colour entries by: Activity group'; click a value to hide or show it).
* **Which columns and contacts separate nematode-active from insect-active toxins**: see `docs/nematode_vs_insect_separation.md`. Seven alignment columns and ten residue-residue contacts (mostly in the C-terminal protoxin module) are shared by the nematode families (Cry5, 12, 13, 14, 21, 95) and rare among insect-active toxins; they survive leave-one-nematode-family-out validation (mean AUC 0.89 and 0.95; random pseudo-nematode families 0.52, p = 0.013 and 0.007). A lineage marker is not shown to be functional; only 17 positives in 6 families. The columns are marked on the alignment (teal stars).
* **Domain trees entry by entry** (`25_domain_trees.py`, `docs/domain_tree_discordance.md`): for every entry the majority name group (Cry1A, Cry1B ...) of its 10 nearest relatives in the Domain I, II and III trees. 347 of 667 entries can be judged: 97 % concordant, 11 differ in one domain (8 in Domain III: Cry1B, Cry1C, Cry1E, Cry1J entries), 2 differ in all three. Noise from the alignment replicate is 0-1 %. The rest cannot be judged (their nearest relatives do not share a name group). The default tanglegram is Domain II against Domain III. Attribute 'Domain trees' in the colour-by bar.
* **Ligand-site layer** (`23_ligand_site.py`): residues within 4.5 A of the bound N-acetylgalactosamine in PDB 4ARY (Cry1Ac): F481, F483, I508, Q509, N510, R511, Y513, R590 (all Domain III), mapped to the structure-frame columns and marked with diamonds on every row. They are poorly conserved (7-27 % of entries share the Cry1Ac residue; about 20 % even within Cry1). `python 23_ligand_site.py <mmCIF> <row id> [ligand ids]` does the same for another structure.
* Order of the scripts: 19 (build) -> 22 / 23 / 24 / 25 -> 27 (writes into the pack; run it again after every 19).

## Tree window with rows in another order (2026-11-27)
* The tree window beside the alignment used to need the rows in the order of its tree (ML tree order); with Order = Name it showed only a note. `scripts/patch_cry_linked_tree.py` (applied in place to `site/index.html` after `patch_cry_page.py` and the downloads patch; idempotent) lets the ML tree keep its own leaf order next to rows in any other order: tip k stands at the k-th row position (same row height and scrolling as the rows) and a line, coloured by family class, joins each tip to its row. The crossings show how far the order of the rows (here the names) differs from the tree. No data file changed: the tree is the ML tree of the frame on screen (struct_A / seq_A of `trees.json`), so it follows the Structure / Sequence switch.
* Entries picked, on screen or hovered, and the clade under the pointer, are drawn bold with their rows highlighted; clicking a node picks the clade, clicking a tip or a row opens the entry, as before. The button **Rows by tree** in the control bar of the window (shown only while the rows are in another order) puts the rows in tree order; opening the window no longer re-sorts rows that are listed by Name (or by a curation order), other orders are still switched to the tree order when the window opens.
* **Name-order tree (second choice in the tree window)**: a tree calculated from the entries in Name order, for the structure-based and the sequence-based alignment (`scripts/28_name_order_trees.py` -> `trees.json` `name_order`, with the Name order itself so that tips and rows cannot disagree between browser locales; `scripts/patch_cry_name_tree.py` adds it to the page after the linked-tree patch). Method: average-linkage clustering (UPGMA) in which only clusters that are neighbours in the Name list may be joined; distances = Kimura protein distance, d = -ln(1 - p - 0.2 p^2), p = fraction of differing residues over the columns where both entries have a residue, in the 1,402 (structure frame) / 1,261 (sequence frame) columns occupied by >= 20 % of the entries (the columns of the full-toxin ML trees); pairs that share < 50 such columns (4 pairs) get the largest distance. Node height = mean distance / 2, raised to the height of the children where the constraint makes a later join smaller than an earlier one (152 of 669 joins in the structure tree, 140 in the sequence tree; zero-length branches). With Order = Name its tips are level with the rows (no lines); in other orders it is joined to the rows by lines like the ML tree. Selecting it puts the rows in Name order; selecting the ML tree while the rows are listed by Name keeps the Name order and draws the lines; Order = ML tree switches back to the ML tree.
* **What it is not**: a maximum-likelihood tree. Only name neighbours can be joined, so deep joins are forced by the name list (Cry10 ... Cry19, then Cry1Aa ..., follow the character-by-character sort, not the relationships) and no ancestors exist for it (a click picks the entries only). Correlation of the distances read from the tree with the pairwise distances (cophenetic r): 0.50 (structure) and 0.54 (sequence), against 0.95 and 0.93 for the same clustering without the order constraint. Close neighbours (variants of one gene, neighbouring genes of a family) are drawn reliably; use the ML tree for relationships between families.
* Order of the scripts: 20 (trees; REPLACES trees.json) -> 28 (name-order trees; run with `py`, not `-I`, to store the unconstrained reference r) -> page patches: `patch_cry_page.py`, the downloads patch, `patch_cry_linked_tree.py`, `patch_cry_name_tree.py`.
